## About

BloxStrike is an **educational project** designed to help developers learn:

- Lua programming techniques
- Module architecture patterns
- Game integration methods
- Documentation best practices

We welcome contributions that enhance the educational value of this project.

## How to Contribute

### 🐛 Report Bugs

If you find a bug:

1. Check existing issues first
2. Create a new issue with:
   - Clear description
   - Steps to reproduce
   - Expected vs actual behavior
   - Environment details

### 💡 Suggest Features

Feature suggestions should:

1. Have educational value
2. Be well-documented
3. Follow existing patterns
4. Include examples

### 📝 Improve Documentation

Documentation contributions are welcome:

1. Fix typos or errors
2. Add examples
3. Improve clarity
4. Translate to other languages

### 🔧 Submit Code

Code contributions should:

1. Follow coding standards
2. Include documentation
3. Add tests if applicable
4. Be well-commented

## Development Guidelines

### Code Style

```lua
-- Use 4 spaces for indentation
local function example()
    -- Comment complex logic
    return true
end
```

### Naming Conventions

- **Variables**: `camelCase`
- **Functions**: `camelCase`
- **Constants**: `UPPER_CASE`
- **Tables**: `PascalCase`

### Documentation

- Comment complex algorithms
- Explain non-obvious logic
- Include examples where helpful
- Keep comments up-to-date

### Testing

- Test on multiple platforms
- Verify error handling
- Check performance impact
- Document test results

## Pull Request Process

### Before Submitting

- [ ] Code follows style guidelines
- [ ] Documentation is updated
- [ ] Changes are tested
- [ ] Commit messages are clear

### PR Template

```markdown
## Description
Brief description of changes

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Documentation
- [ ] Other

## Educational Value
How does this help learners?

## Testing
- [ ] Tested locally
- [ ] No errors
- [ ] Works as expected
```

### Review Process

1. **Initial Review**: Check for completeness
2. **Code Review**: Verify quality
3. **Testing**: Ensure functionality
4. **Merge**: If all checks pass

## Code of Conduct

### Our Standards

- Be respectful and inclusive
- Focus on learning
- Provide constructive feedback
- Help others grow

### Unacceptable Behavior

- Harassment or discrimination
- Offensive language
- Spam or self-promotion
- Malicious contributions

## Questions?

If you have questions:

1. Check existing documentation
2. Search GitHub Issues
3. Open a new issue with `question` label

## Thank You!

Your contributions help make this project better for everyone. Thank you for taking the time to contribute to this educational resource!
